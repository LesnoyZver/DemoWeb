# Демо-магазин аксессуаров для техники

Минималистичный интернет-магазин в чёрно-белой стилистике: серверный рендеринг
на FastAPI + Jinja2, SQLite, немного vanilla JS для корзины. Есть админка для
пополнения каталога и работы с заказами.

## Запуск за 5 шагов

```bash
# 1. Перейти в папку проекта
cd /Users/goncharov/Programming/DemoWeb

# 2. Создать и активировать виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать .env и задать пароль администратора
cp .env.example .env
# отредактируйте .env: SECRET_KEY (длинная случайная строка) и ADMIN_PASSWORD

# 5. Запустить сервер
uvicorn app.main:app --reload
```

Сайт: <http://127.0.0.1:8000>
Админка: <http://127.0.0.1:8000/admin>

При первом запуске автоматически создаются `data/shop.db`, схема и демо-данные:
3 категории, 12 товаров и монохромные изображения 800×800 (генерируются локально
через Pillow). Если БД уже содержит товары, seed не выполняется. Каталог данных
(`shop.db` и `uploads`) задаётся переменной `DATA_DIR` (по умолчанию `./data`).

> В текущем окружении проекта `.venv` уже создан, зависимости установлены,
> `.env` заполнен (`ADMIN_PASSWORD=admin123`). Достаточно шага 5.

## Доступ в админку

Пароль берётся из `ADMIN_PASSWORD` в `.env`. В демо-конфигурации — `admin123`.
`SECRET_KEY` используется для подписи сессионной cookie. Без переменных
окружения `SECRET_KEY` и `ADMIN_PASSWORD` приложение не запускается.

## Деплой на Render

В репозитории уже есть `Dockerfile`, `.dockerignore` и `render.yaml`.

1. Закоммитьте изменения и отправьте репозиторий на GitHub:

   ```bash
   git add .
   git commit -m "Prepare Docker/Render deployment"
   git push origin main
   ```

2. В панели Render нажмите **New → Blueprint** и подключите GitHub-репозиторий
   с проектом.
3. Render прочитает `render.yaml` и предложит создать web-сервис (`runtime: docker`,
   план `free`). Подтвердите создание.
4. Задайте `ADMIN_PASSWORD` (пароль входа в админку). `SECRET_KEY` Render
   сгенерирует автоматически, а `DATA_DIR` уже равен `/app/data`.
5. Нажмите **Deploy** и дождитесь окончания сборки: health-check `GET /health`
   должен возвращать `200`.
6. Откройте публичный URL сервиса (вида `https://<имя-сервиса>.onrender.com`) —
   каталог с демо-товарами загрузится автоматически.

> ⚠️ На бесплатном тарифе Render диск не сохраняется между перезапусками.
> `shop.db` и загруженные изображения в `/app/data` живут только внутри текущего
> контейнера: после передеплоя, перезапуска или засыпания сервиса товары,
> заказы и загрузки пропадут, а демо-набор будет создан заново. Для постоянного
> хранения данных нужен платный план с persistent disk.

## Структура

```
app/
  main.py            — приложение, lifespan (БД + seed), статика, сессии
  db.py              — sqlite3, схема, параметризованные запросы, slugify
  auth.py            — пароль из .env, проверка сессии
  routes_public.py   — главная, каталог, товар, корзина, оформление
  routes_admin.py    — вход, дашборд, товары, категории, заказы
  seed.py            — демо-данные и плейсхолдеры через Pillow
  templating.py      — общий Jinja2-окружение и фильтры (BYN, даты, статусы)
  templates/         — HTML-шаблоны (публичные и admin/)
  static/
    css/style.css    — единственный CSS-файл
    js/app.js        — корзина, превью загрузки, клиентская валидация
    uploads/         — загруженные и сгенерированные изображения
README.md
requirements.txt
.env.example
```

## Что реализовано

- Главная: hero, 4 новинки, короткий футер.
- Каталог: сетка карточек, фильтр по категориям, сортировка по цене и новизне.
- Товар: большое изображение, описание, цена, «В корзину».
- Корзина: `localStorage`, изменение количества и удаление; при оформлении
  сервер пересчитывает стоимость по актуальным ценам из БД.
- Оформление: имя, телефон, e-mail, адрес; валидация на клиенте и сервере;
  после заказа — страница «Заказ принят». Оплата не подключена.
- Админка: дашборд; товары (добавить/редактировать/скрыть/удалить с
  подтверждением); загрузка JPG/PNG/WEBP до 3 МБ с превью и безопасным именем;
  категории (добавление/переименование); заказы (состав, статусы
  `new → in_progress → done`).
- Все SQL-запросы параметризованы, Jinja2 с автоэкранированием, админ-маршруты
  закрыты проверкой сессии, загрузки валидируются по сигнатуре и размеру.

## Автоматическая проверка (выполнена при разработке)

Пункты 1–2 из критериев готовности проверены запуском сервера и HTTP-запросами:

1. `uvicorn app.main:app` стартует без ошибок; `shop.db` и демо-данные
   создаются автоматически.
2. Все публичные страницы (`/`, `/catalog`, `/product/{slug}`, `/cart`,
   `/checkout`) возвращают 200; `/admin` без входа отвечает редиректом на
   `/admin/login`.

Повторить вручную:

```bash
uvicorn app.main:app --reload
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/catalog
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/cart
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/checkout
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://127.0.0.1:8000/admin
```

## Чек-лист ручной проверки (визуально не проверялось)

Пункты 3–4 требуют браузера — ниже сценарий для ручной проверки.

### 3. Товар из админки появляется в каталоге

1. Откройте <http://127.0.0.1:8000/admin>, введите пароль из `.env`.
2. «Товары» → «Добавить товар».
3. Заполните название, категорию, цену и описание.
4. Выберите JPG/PNG/WEBP до 3 МБ — под полем появится превью.
5. Оставьте галочку «Опубликовать на сайте» и нажмите «Создать товар».
6. Убедитесь, что товар есть в списке админки.
7. Откройте «Каталог» на сайте (или обновите страницу) — товар отображается.
8. Проверьте «Скрыть» в админке: товар исчезает из каталога; «Показать» —
   возвращается.

### 4. Вёрстка на 375 / 768 / 1280 px

Откройте DevTools → Toggle device toolbar и проверьте ширины:

- **375 px** — шапка не переполняется, карточки в 1–2 колонки, форма оформления
  в одну колонку, таблицы админки скроллятся горизонтально.
- **768 px** — карточки в 2 колонки, страница товара в одну колонку, сайдбар
  админки становится верхней навигацией.
- **1280 px** — карточки в 4 колонки, страница товара в две колонки, контент
  центрирован с максимальной шириной 1200 px.

Дополнительно: hover на карточке плавно увеличивает изображение (scale 1.03,
200 мс), кнопки и границы остаются в чёрно-белой палитре.
